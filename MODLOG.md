# Terraria in Stardew Valley

## Routes

- Host: Stardew Valley 1.6.15.24356 on macOS x64.
- Guest: Terraria 1.4.5.8 data in the local macOS app bundle; native macOS launcher available.
- Loaders: SMAPI 4.5.2 for Stardew Valley and tModLoader 2026.08.3.0 for Terraria.
- Initial prototype route: asset/content conversion through the SMAPI loader API.
- Target route after clarification: keep Stardew and tModLoader running as separate processes; Stardew remains the main window and displays a Terraria video stream while forwarding controls over localhost. Each game remains authoritative for its own simulation and save.
- Reason for keeping the prototype: it provides a small host-native vertical slice and a fallback mode while the bridge is being built. It does not claim that Terraria is already running inside Stardew.

## First slice

`Meteor Blade` is registered by editing Stardew's `Data/Weapons` asset. The weapon uses a stable qualified ID, Terraria-inspired values, and a console command that grants one copy for testing.

## Safety

- No game files, decompiled source, or extracted Terraria assets are shipped.
- The built mods are installed in the local SMAPI and tModLoader profiles. Keep a backup of saves before testing.
- Test on a copied Stardew save. Back up saves before the first modded launch.

## Known limitations

- The two game processes remain separate. Stardew displays a low-resolution live Terraria frame and forwards controls; tModLoader owns Terraria world simulation, AI, collision and save data.
- The tModLoader-side input injection, live frame transport, Stardew F8 toggle handler, and real Stardew keyboard/mouse control are verified. The remaining limitation is presentation quality: the Terraria stream is lower resolution than the native window.
- The first slice does not yet add monsters, world generation, or mine rooms.
- The weapon uses a Stardew sprite-sheet placeholder until a new, original sprite is added.
